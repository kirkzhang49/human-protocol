# Human Protocol

A standalone first-person 3D escape-room / combat prototype built with Vite, React, TypeScript, Three.js, and a Raw WebGPU runtime path. This repository contains the playable game, builder tools, cooked runtime assets, Raw WebGPU manifests, Blender/source assets, asset-build scripts, and the Human Protocol Codex skill handoff docs used to keep the 3D pipeline reproducible.

Game id: `human-protocol`

## Run

```bash
npm install
npm run dev
```

The Raw WebGPU playtest path requires a browser with WebGPU enabled.

## Standalone Repository Layout

- `src`: game/runtime source plus committed runtime assets.
- `public/assets/human-protocol/raw-webgpu`: split Raw WebGPU runtime resource packs used by builder/deep playtests.
- `scripts/asset-build`: Blender, Image2, GLB, texture, and Raw WebGPU asset pipeline scripts.
- `src/assets/source_blend`: source `.blend` files for generated weapons, props, enemies, pickups, and environment assets.
- `work`: reference intake, scripted-derived intermediates, and QA working assets that are useful for regenerating the 3D pipeline.
- `packages/age-render-webgpu`: vendored local renderer slice formerly imported from the monorepo.
- `docs/codex-skills`: Human Protocol Codex skills copied into the repo for handoff and future agent runs.

Generated local folders such as `node_modules`, `dist`, `.tmp`, and `tmp` are intentionally not committed. The oversized generated builder runtime geometry file `src/assets/manifests/generated/raw-webgpu/render_plan_builder_runtime_resources_geometry.bin` is also ignored because the current runtime uses split resource packs and the large file can be regenerated by the Raw WebGPU pipeline when needed.

## Platform Build

```bash
npm run build:platform
npm run package:platform
```

`build:platform` runs a production build, package budget checks, file-count checks, and relative-path validation for HTML5 platform hosting.
`package:platform` also writes `human-protocol-crazygames.zip` from the built `dist` contents.

## Controls

- Mobile landscape: left thumb moves, right thumb turns, `棒` selects the heavy lab iron rod, `枪` selects the 20-shot pistol, and `大招` fires the core ultimate.
- `WASD`: move.
- Desktop mouse: start, upgrade picks, revive, and replay automatically lock cockpit aim when returning to gameplay.
- Move the mouse while locked to turn camera.
- If pointer lock is unavailable, hold left or right mouse and drag to turn.
- Left mouse: manual fire input; auto-fire still handles locked targets.
- Title, upgrade, death, and victory screens show the normal cursor; clickable buttons/cards use the hand cursor.
- `Space`: core ultimate.
- `1` / `2` / `3`: iron rod / pistol / ultimate selection.
- `Escape`: exits cockpit aim first; press again to pause or unpause.

## Architecture

- `src/game/core`: mutable world state, timing, math, and loop orchestration.
- `src/game/config`: level manifest, wave data, enemy archetypes, upgrade pool, dialogue, and balance.
- `src/game/entities`: typed player robot, projectile, enemy, obstacle, and effect state.
- `src/game/systems`: frame systems that mutate `GameWorld` without pushing 60 FPS movement into React state.
- `src/game/audio`: Web Audio synth fallback keyed by gameplay audio ids.
- `src/game/skins`: visual skin data, material colors, visibility flags, scale multipliers, and weapon hardpoints.
- `src/render`: React Three Fiber renderers that read the current `GameWorld` and update mesh refs imperatively.
- `src/ui`: DOM HUD, mobile controls, dialogue, upgrade, flow, and debug overlays.
- `src/input`: keyboard and pointer input collection.

## Adding A Robot Skin

To add a new robot skin without touching core gameplay:

1. Add a new `RobotSkinId` value in `src/game/skins/SkinTypes.ts`.
2. Create a `RobotSkin` object in `src/game/skins/robotSkins.ts`.
3. Set its colors, PBR material values, glow intensity, scale multipliers, part visibility, and weapon hardpoints.
4. Keep hardpoint ids compatible with the weapon renderer or add typed ids when adding new visible weapon mounts.
5. Assign the new skin id in `createPlayerRobot` or expose a future UI selector.

Gameplay systems read hardpoints and skin ids through typed data. Movement, aiming, dash, projectile spawning, and camera logic do not need skin-specific branching.

## Extension Notes

- Add enemies as `EnemyState` plus dedicated systems for spawn, steering, damage, and death effects.
- Add weapons through `weaponConfig`, `weaponSkins`, and `WeaponSystem` fire modes.
- Add mobile controls as a new input adapter that writes to the same `WorldInputState`.
- Add imported 3D models later by replacing or extending `RobotRenderer`; keep `RobotState` and systems unchanged.
